# Languages

Arctic speaks several languages: the launcher and the Arctic Client (the in-game mod) both.
**Every piece of text people see is localized**, and `tools/i18n_check.py` (run in CI) fails the
build when a raw English string reaches the interface, when a key is missing from English, or
when a language is incomplete.

| Code | Language | Code | Language |
|---|---|---|---|
| `en` | English (the source) | `it` | Italiano |
| `tr` | Türkçe | `nl` | Nederlands |
| `de` | Deutsch | `pl` | Polski |
| `fr` | Français | `ru` | Русский |
| `es` | Español | `uk` | Українська |
| `pt` | Português (Brasil) | `zh` | 简体中文 |
| `ja` | 日本語 | `ko` | 한국어 |

The launcher's language is picked in Settings → Appearance ("System" follows the computer's
language). The game follows the launcher's pick (sent in `config/arctic-session.json` at launch);
when the launcher is on "System", the mod uses the game's own language instead, so a player who
set Minecraft to Turkish sees Arctic's menus in Turkish too. Both fall back to English for a
language Arctic doesn't speak, and to English per text for anything not yet translated.

## Where the text lives

Flat JSON objects, `"key": "text"`, UTF-8, one file per part of the interface (an *area*):

```
crates/arctic-app/locales/<code>/<area>.json                       launcher
mod/core/src/main/resources/assets/arctic/lang/<code>/<area>.json  Arctic Client
```

English is the source of truth: every key exists in `en/`, and every other language has exactly
the same keys. The launcher embeds its files at build time (`build.rs` finds every file under
`locales/`, nothing lists them); the mod loads its areas by name (`Lang.AREAS`).

Launcher areas: `common`, `nav`, `play`, `accounts`, `instances`, `skins`, `social`, `settings`,
`tasks`, `core`. Mod areas: `common`, `mods`, `hud`, `social`, `looks`, `servers`,
`replay`, `platform`. A key's first segment is its area (`settings.memory.title` lives in
`settings.json`), except `common.*`, shared words every area may use (OK, Cancel, Close…).

### Keys

`area.slug`, lowercase, dots between segments, underscores inside a segment. Most keys are the
English text's slug (`settings.show_snapshots` for "Show snapshots"), which is what
`tools/i18n_extract.py` makes; tables of choices use a short name (`settings.theme.aurora`).
The same text in one area shares one key. A rewording may keep its key.

Placeholders are `{name}` in the launcher (`"Ready in {seconds} s"`) and `{0}`, `{1}`… in the
mod (`"Joined {0}"`); counts use `{n}`. A translation keeps the same placeholders, in whatever
order its grammar wants.

Plurals: `key.one`, `key.few`, `key.many`, `key.other` (English only needs `one` and `other`;
Russian, Ukrainian and Polish use all of `one`, `few`, `many`; French and Portuguese treat 0 as
`one`; Chinese, Japanese and Korean have only `other`). The code picks the form from the number.

## In the launcher (Rust, `crates/arctic-app`)

```rust
use crate::{t, tf, tn};

ui.label(t!("settings.title"));                       // &'static str: goes wherever a literal went
ui.button(tf!("play.ready_in", seconds = left));      // String, "{seconds}" filled
ui.label(tn!("instances.mods_count", mods.len()));    // String, picks .one/.other…, fills {n}
```

- `t!` returns `&'static str`, so match arms, `const` tables of `&str` and function parameters
  typed `&str` keep working. A `const` can't call it: store keys in the table and call `t!` where
  the text is shown.
- `format!("Installing {name}…")` becomes `tf!("tasks.installing", name = name)`. Text with a
  count becomes `tn!`.
- Text the code compares against, or uses as an id, is not display text: keep the literal, and
  translate where it's shown. A key for an `Id` or `id_salt` stays a literal.
- Text from `arctic-core` (progress stages, a few messages) is shown through
  `crate::i18n::core_text(&stage)`, which looks up `core.<English text>` in the `core` area.
- `crate::i18n::lookup("dynamic.key")` for a key built at run time (returns `Option`).
- A literal that is not text people see but the checker flags: add `// i18n-ignore` on its line.

The language is set at start (`i18n::set_language`), when a profile is switched, and from the
picker; nothing else needs to know. `i18n::ensure_fonts` loads a script's system font (Chinese, Japanese, Korean)
when such a language is in use.

## In the Arctic Client (Java, `mod/core` and the version adapters)

```java
import com.arcticlauncher.client.Lang;

new Label(Lang.t("mods.title"), Label.Kind.SECTION);
Notices.post(Lang.t("social.friend_joined.title"), Lang.t("social.friend_joined.body", name));
f.toggle(Lang.t("mods.zoom.smooth"), Lang.t("mods.zoom.smooth.hint"), get, set);
String count = Lang.plural("servers.players_online", n);   // {n} filled; {0}… from more args
```

- `Lang.t(key)` returns the text; `Lang.t(key, a, b)` fills `{0}`, `{1}`.
- The language is chosen once, in `ArcticClient.init` (before the HUD and menus build their
  text), so names stored in fields (`HudWidget.name`, `Mod.description`) are already translated.
- Text used as an identity (a `Notices.relabel` label, a key stored in config, an id compared with
  `equals`) stays a literal; translate at the display site.
- Version adapters (`mod/versions/*`) use `Lang` too; keep the `//#if MC …` preprocessor blocks
  exactly as they are around any text they hold.
- Log messages, mixin targets, resource paths and Minecraft's own translation keys
  (`Platform.translate(key, english)`) are not display text.

## Translating

- Match the tone: short, plain, friendly, second person, no exclamation marks the English
  doesn't have. Fit the space: a button label stays a few words.
- Keep placeholders and plural forms; keep brand names (Arctic, Minecraft, Modrinth, Fabric…),
  key names (Right Shift stays as the game shows it) and technical terms people search for
  (FPS, HUD, ping).
- Don't translate `tools/i18n_allow.txt` words, ids, or anything that isn't in `en/`.

## Adding a language

1. Create `crates/arctic-app/locales/<code>/` and `mod/core/src/main/resources/assets/arctic/lang/<code>/`
   with every area file translated from `en/`.
2. Add it to `LANGUAGES` in `crates/arctic-app/src/i18n.rs` (its code, its own name, and a sample
   character if its script isn't Latin or Cyrillic, so its font loads) and to `CODES` in
   `mod/core/src/main/java/com/arcticlauncher/client/Lang.java`.
3. If its plural rules aren't English's, add them to `plural_form` / `pluralForm` in both.
4. `python tools/i18n_check.py` until it's happy.

## Checking

```
python tools/i18n_check.py            # what CI runs; exit code 1 on any problem
python tools/i18n_check.py --verbose  # counts per language, texts left identical to English
python tools/i18n_check.py --unused   # English keys no code uses (a warning)
```

`cargo test -p arctic-app i18n` and `mod/gradlew -p mod/core test --tests '*LangTest*'` check
the catalogs from inside each program as well.
